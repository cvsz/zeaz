# Roadmap ของ MooPiew

Roadmap นี้อธิบายทิศทางของแพลตฟอร์มร้านอาหาร ไม่ได้หมายความว่าฟีเจอร์ marketplace หรือ
การจ่ายเงินทุกชนิดเปิดใช้งานแล้ว กำหนดการต้องทบทวนตามการอนุมัติของร้านค้า กฎหมาย และการปฏิบัติงาน

## สิ่งที่ทำแล้ว

- สั่งล่วงหน้ารับที่ร้านและจัดส่งโดยคำนวณราคาตามระยะทาง
- เมนู สต็อก/สูตร คูปอง แต้มสะสม ใบเสร็จ และ audit history
- หน้าจัดการเจ้าของ ใบสมัครไรเดอร์/ร้านค้า จัดการไรเดอร์ และติดตามการส่ง
- สำรอง SQLite, deploy ผ่าน Cloudflare Tunnel, health check และเอกสาร API
- วางขอบเขต SCB, Sandbox preflight และยืนยันการจ่ายจาก inquiry เป็นหลัก โดยปิด live payment เป็นค่าเริ่มต้น

## ลำดับถัดไป: ทำงานได้มั่นคง

1. ตรวจ master data, SLA การส่ง และ checklist ยืนยันตัวไรเดอร์
2. เพิ่มสิทธิ์ใช้งานเฉพาะไรเดอร์ แทนการใช้สิทธิ์ของเจ้าของร่วมกัน
3. เพิ่มรายงาน export/reconciliation, นโยบายเก็บข้อมูล และ runbook เหตุการณ์
4. ซ้อม restore backup, ยกเลิก/คืนเงิน และงานส่งล้มเหลว

## ลำดับถัดไป: การชำระเงินและพาร์ตเนอร์ที่เชื่อถือได้

1. ทดสอบ SCB Sandbox QR แบบ end-to-end ด้วย credential ที่อนุมัติ, Transaction Inquiry และ callback signature
2. ขออนุมัติ production หมุน secret และเปิดใช้ด้วย feature gate
3. สร้าง portal สิทธิ์จำกัดสำหรับร้านค้าที่อนุมัติ และรองรับหลายสาขาโดยเก็บ audit trail

## ระยะขยายผล

- หลายสาขา แคตตาล็อก พื้นที่บริการ ค่าคอมมิชชัน และรายงาน settlement
- แอปลูกค้า/ไรเดอร์ที่ใช้ API contract เดียวกัน
- ย้ายไป relational database และ worker เมื่อปริมาณงาน/การกู้คืนจำเป็นจริง

## นิยามของเสร็จ

แต่ละงานจะถือว่าเสร็จเมื่อมีเจ้าของงาน ขอบเขตความปลอดภัย วิธีทดสอบ metric การปฏิบัติงาน และทางย้อนกลับ
ที่บันทึกและทดสอบในสภาพแวดล้อมที่ไม่ใช่ production แล้ว
